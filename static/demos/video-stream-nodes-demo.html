视频流的分层节点架构：stream、节点与输出接口

视频输出不是一根数据线，而是一组按职责分层的组件：业务 / 上位机、固件服务、驱动、硬件 IP。本页用四层泳道拆开stream、节点序列与输出接口的真实边界——谁配参数、谁管生命周期、谁写寄存器、谁搬像素。

1分层模型：四层各管一段

视频输出按职责分为四层：业务 / 上位机下配置，固件服务管生命周期与节点序列，驱动写寄存器，硬件做实时处理与搬运。数据在硬件链路流动，CPU 不逐节点复制像素。

层职责典型对象
业务 / 上位机下配置、消费帧Windows UVC、外部 CSI-2 RX
固件服务Stream FSM、节点序列、输出管理stream、node
驱动ISP / Video / 接口设备控制DMA、寄存器
硬件实时处理、DMA、物理接口Video IP、Stream MUX / SEL
分层原则：上层不碰寄存器；硬件事件不自动变成帧就绪回调，状态机始终由显式命令驱动。
业务下配置 → 服务管生命周期 → 驱动写寄存器 → 硬件搬像素

2各路流职责：PIC / TEMP / VS

PIC、TEMP 与 VS 共享同一套分层框架，但各有不同的处理序列与输出语义：PIC 是观察图，TEMP 是测温面阵，VS 是轻量视频转接。处理序列由 vtable 与生成序列区分。

流处理序列语义
PIC两级 Cut/Zoom → PSD → OSD×2 → SOUT → OUT观察图
TEMP两级 Cut/Zoom → PSD → OUT测温面阵
VS1/2/3两级 Cut/Zoom → OUT视频转接
注意：PIP 是 PIC 子流语义，不是与 PIC/TEMP/VS 同级的独立 stream；Y16 是容器，不等于摄氏温度。

3节点生命周期：装配、启动、停止与回滚

节点序列由配置驱动，按固定顺序装配、失败逆序回滚；启动只打开对应 ISP 流数据门，物理接口可能在初始化阶段已就绪。READY、RUNNING、接口 Ready 与接收端看到完整帧是四个独立成功边界。

阶段动作成功边界
装配流 → 节点 → 驱动初始化READY
启动START 开 ISP 流数据门RUNNING
停止 / 去初始化STOP 关流 / DEINIT 停 + 解绑READY / IDLE
注意：接口生命周期不能一概写成"INIT 即开始送帧"。UVC 的 Commit 与业务 START 是两个独立门槛。
装配：流初始化 → 节点初始化 → 驱动初始化
失败：逆序回滚
启动：START 开数据门 → RUNNING
停止：STOP → READY；DEINIT → IDLE

4输出接口：SINGLE 与 COMPOSE

软件输出接口负责资源绑定与生命周期，硬件 MUX / SEL 负责源流到物理接口的路由，两者分层解耦。SINGLE 单接口直出，COMPOSE 组合 / 共享需前置条件一致；一条流可绑一个或多个接口。

模式行为约束
SINGLE一条流绑一个接口简单直接
COMPOSE多路 / 共享输出宽度、帧率、模式须一致
可选接口VOC / VOSPI / MJPEG是否支持取决于具体实现
关键区分：软件输出口不是硬件 MUX/SEL；MIPI 进 Windows 必须经外部桥片 / 主控实现 USB/UVC，不能画成直连。
USB 分支 → Windows UVC（USB endpoint + data type）
MIPI 分支 → 外部 CSI-2 RX（VC + data type）
两个接收端不能合成同一个"PC 接收端"

5组合与边界：能力、格式与前置条件

路由表可以先行覆盖全部类型，但处理器能力是逐项补齐的；格式统一管理仍是待办目标。占位类型应返回明确的不支持状态而非静默。

边界现状约束
OSD Type2 / Rec已实现Rec 输入固定 YUV422
OSD Type1 / Time占位返回不支持
格式统一待办PSD 与 OSD 共享 FORMAT 资源有竞争风险
接口前置共享宽度 / 帧率 / 模式不一致则拒绝或切换
踩坑：不要把设计目标描述成已实现的能力；格式切换绕过统一状态时，要留意共享资源竞争。

一句话总结

视频输出是一组按职责分层的组件：业务下配置、固件服务管生命周期、驱动写寄存器、硬件做实时处理；PIC/TEMP/VS 共享框架但各有序列，输出接口与硬件路由分层解耦，能力与格式边界需逐步验证。
