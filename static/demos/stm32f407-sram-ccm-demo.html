结论 四问先答

先给结论，后面逐条用动画展开。
Q1 · CCM 为什么是 CPU 独占？
只有 CPU 的 D-Bus 有到 CCM 的私有直连。DMA、外设都没接这条线 —— 别人进不来。所以 UART/USB/ADC 的缓冲放 CCM，数据根本送不进去。
Q2 · CCM 为什么"零等待"？
专线绕过总线矩阵，不用和 DMA/外设排队竞争仲裁。SRAM 要走矩阵，与 DMA 并发时会插等待周期 —— 差距就在这里。
Q3 · CCM 能执行代码吗？
不能。取指靠 I-Bus，CCM 只挂了数据总线（D-Bus），没挂 I-Bus。代码放 CCM 会 HardFault。CCM 只放数据。
Q4 · RAM1 就是一块 128KB 内存吗？
不是。RAM1 是 SRAM1(112KB) + SRAM2(16KB) 的链接合并别名。物理上是两块 SRAM，地址连续后链接器合成一个区。

拓扑 Cortex-M4 的三条通路与一堵"看不见的墙"

Cortex-M4 有两条总线：I-Bus（取指，连 Flash/SRAM，不连 CCM）和 D-Bus（数据，既经总线矩阵到 SRAM、又有一条私有直连到 CCM）。DMA 与外设只能走总线矩阵 —— 那条路到不了 CCM。

决策 数据放哪：三问三不放

问题回答放置
会被 DMA / 外设读写吗？是（串口缓冲、USB FIFO、ADC 数组）SRAM / RAM1（必经 DMA 可见区）
会被 CPU 取指执行吗？是（bootloader、RAM 常驻 ISR）SRAM
纯 CPU 数据、访问极频繁？是（事件池、热线程栈）CCM（零等待）
低频、容量大、凑热闹？是（日志缓冲、冷配置）SRAM（别浪费 CCM）

三个绝不放：① DMA/外设缓冲绝不放 CCM（数据到不了）；② 可执行代码/ISR 绝不放 CCM（取指走 I-Bus，没接）；③ 又大又冷的对象别放 CCM（占坑挤掉真热数据）。

  • CCM 不能 DMA —— 串口/USB DMA 缓冲放 CCM，数据永远不到达（DMA 走总线矩阵，无路径）。
  • CCM 不能执行代码 —— 取指走 I-Bus，CCM 只挂了数据总线，函数/ISR 放进去会 HardFault。
  • CCM 不在位带映射区 —— 位带变量放 CCM 段，"链接通过、运行出错"：位操作退化成整字读改写，丢原子性。
  • RAM1=128KB 是合并区 —— 它含 SRAM2 的 16KB，写 SRAM 时别以为只剩 SRAM1。
  • 链接脚本是最终裁决 —— 宏（如 section(".ccm_bss")）只是把对象放进 section，真正落位由 link.lds 的 MEMORY/SECTIONS 决定。
