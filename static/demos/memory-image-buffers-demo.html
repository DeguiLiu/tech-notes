图像缓冲的内存管理：从链接布局到 DMA 闭环

视频处理系统里，一帧图像要在多个缓冲区之间流转。它的地址怎么确定、对象放哪、CPU 与 DMA 如何保持一致、连续布局怎么分配——这条内存管理链贯穿构建、链接、运行时与硬件。每一节配一个交互动画，讲清机制后直接演示。

1地址从哪来：构建变体、链接脚本与 LMA/VMA

一块图像缓冲的地址不是运行时决定的，而是构建期选定变体、链接期落地、运行期由启动代码搬移。三者缺一不可。

环节职责产物
构建变体按基线/内存类型选择脚本分支与宏决定 MEMORY 区域与镜像参数
链接脚本定义区域容量与 section 落点LMA / VMA / 起止符号
启动代码执行 copy（LMA→VMA）与清零（BSS/UNINIT）运行期对象就位
关键区分：LMA 是镜像保存位置，VMA 是运行访问位置。有初值 section 同时有 LMA 和 VMA；无初值 section 只需 VMA 并清零。最终要以本次 ELF/map 核对地址、大小与溢出——旧 map 不是当前结果。

2对象放哪：静态池与堆的分工

图像对象按生命周期特征分两类安置：模块级对象进专用段（静态池），动态对象从系统堆分配。

方式特点适用
静态池（专用 section）容量固定、生命周期确定、零碎片Video / ISP 图像对象
系统堆（动态分配）运行时可变、需对齐管理通用动态对象、临时缓冲
注意：静态池与堆都在内存区但不可混用。静态池耗尽应调整资源/链接容量，而不是退回动态分配——否则固定延迟与确定性被破坏。

3Cache 一致性：内存属性与 flush/invalidate

CPU 与 DMA 共享同一段内存时，Cache 会让两边看到的数据不一致。同一物理内存在不同属性配置下行为不同。

  • Cacheable 地址交给 DMA：写前 flush、读前 invalidate，按方向维护。
  • 缓冲区需要按 Cache line 与 DMA 对齐（如 Video buffer 64B 对齐、CPU line 32B）。
  • 不可把 CPU data Cache 的失效与"布局失效"混为一谈——两者对象不同。
坑：多帧三缓冲能降低生产者/消费者竞争，但不自动解决 Cache 一致性——一致性必须显式维护。

4DMA 连续布局：从游标到末端地址

ISP / Video 的多路 DMA 需要连续、对齐的地址区间。布局计算按区域顺序与对齐规则连续推进一个地址游标：

入口算各区域长度
  → 按区域顺序 + 对齐规则连续分配
  → 多路三帧缓冲从同一游标连续分配
  → 得到末端地址（一级 DMA 链终点）
  → 超过预留区末端地址 → 返回内存不足

布局由流模式、SOUT、软读、各区域长度共同推动；每个地址都按代码对齐。验证时必须同时核对起点、长度、对齐与最终末端地址。

5布局失效与运行闭环

模式/分辨率变化会推动布局变化，但只有末端地址真的变化才需要失效旧状态：

  • 重排前快照旧终点；终点变化时清除加载路径、重置分配偏移、置初始化标志为否。
  • 清的是加载路径与分配状态，不是 CPU data Cache。
  • 运行期把三缓冲装入流配置后，业务管生命周期，驱动配地址/长度/中断；还需验证完整帧、无旧数据、无越界与正确的 flush/invalidate。
所有权约束：业务不能释放硬件仍引用的 buffer——生命周期必须先于硬件停止。

一句话总结

图像缓冲的地址由构建与链接决定，对象按生命周期分静态池与堆，CPU 与 DMA 靠显式 flush/invalidate 保持一致，DMA 用连续游标布局并受失效与所有权约束——这条链构成了一套确定、可验证的内存管理架构。
