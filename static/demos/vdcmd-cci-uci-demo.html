命令执行核心(vdcmd_parse)两者完全一样,差别只在硬件/软件分工与"结果怎么回来"。支持自动循环与手动单步(上一步/下一步)。

导读 同一条命令，两种邮路

VDCMD 是固件对外的命令接口。同一套解析核心 vdcmd_parse（命令头 CRC 校验 → 三层查表 → rte_write 信号送业务模块）由两条物理通道承载，区别只在"命令怎么进来、结果怎么回来"：

  • CCI（I2C）：命令写进芯片内 CMD_BUF 寄存器信箱，硬件响铃唤醒固件；结果原地写回并翻 CMD_STATUS 牌子，主机自己轮询取回 —— 同步模型为拉取（pull）。
  • UCI（UART）：串口是无边界字节流，固件用软件状态机拆信封；结果由固件主动组回复帧推回，主机 select 阻塞等待 —— 同步模型为推送（push）。

一句话：CCI 靠"硬件成帧 + 主机轮询"，UCI 靠"软件拆帧 + 固件回推"，命令执行核心两者完全相同。

CCI 技术要点

  1. 硬件成帧：I2C 从机是芯片内专用 IP，命令帧边界由 CMD_BUF 寄存器天然界定，无需软件扫描同步字。
  2. 信箱 + 响铃：主机写入 CMD_BUF（寄存器信箱）后，硬件中断"响铃"唤醒 vdcmd 线程。
  3. 命令头：[cmd][sub][len] 三段结构，从机 7-bit 地址固定。
  4. 结果回传：固件把结果原地写回 CMD_BUF，再翻 CMD_STATUS 牌子（busy → done(0)）。
  5. 主机等待：I2C 从机不能主动发起传输，主机只能轮询 CMD_STATUS 再回读 —— 这是 I2C 协议的硬约束。

UCI UART 软件信封 + 主动回推

UCI 技术要点

  1. 软件成帧：UART 是无边界字节流，帧边界全靠固件状态机扫描，硬件不做任何成帧。
  2. 帧格式：同步字 "UCI" + 2 字节小端长度 + VdCMD payload。
  3. 三态状态机：FRAME_SYNC（扫邮戳）→ HEADER_CHECK（读长度并校验）→ PAYLOAD_RX（按长度收满 payload）。
  4. 健壮性：长度范围校验 [min, max]，分包累积，带超时。
  5. 结果回传：固件组回复帧 帧头 | status | data | CRC | 帧尾 主动推回，主机 select 阻塞等待。

选型提示：I2C 适合总线式多设备、命令低频、依赖硬件状态寄存器的场景；UART 适合需要固件主动上报、大数据量回传、主机阻塞等待结果的场景。
