⚠️ 边界：X2 提前封帧与 Identity Zoom 规避 —— 故障现象 / 根源 / 方案 / 证据边界
故障现象ERR+EOF X2 输出时，USB 抓包确认设备在 655360B（=640×512×2B，即 X1 帧字节数）处发送 ERR+EOF → Windows 提前结束该帧，只显示左上约 1/4 画面
根源判断提前封帧 X1→X2 切换时，WRAPE 在 X1 字节边界提前结束 X2 帧（RTL 无正式解释，工程观察）。655360B 对应 X1 的 16-bit 帧字节数，不是 X2 完整帧边界 —— 不称“半帧”
规避方案 · Identity Zoom缩放步长=256 Video Zoom 始终激活、不因切换被复位。X1(640×512) → 2×放大到 1280×1024；X2(1280×1024) → 1:1 恒等直通（缩放步长=256）。即下游固定 1280×1024，USB 对外恒为 1280×1024@30，源流有效计数 1310720 稳定输出完整帧
证据边界工程规避 该方案是工程规避，非 WRAPE RTL 修复；验证须同时看 stream 配置、有效计数、USB 抓包与 Windows 图像，仅“开流成功”不足以证明完整帧
