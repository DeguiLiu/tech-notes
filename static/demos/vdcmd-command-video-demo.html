1命令结构：class / index / subcmd

命令协议用三级字段定位一条命令，参数是定长配置字。多物理入口（CCI / UART / SPI）共享同一格式与解析状态机。

字段作用
class命令大类
index大类内的子项索引
subcmd具体子命令
mode定长配置字（参数）
设计要点：多入口共享同一命令格式与解析状态机，避免每路各写一套协议。构建配置决定启用哪些控制接口。

步骤 1 · 命令帧到达
多入口（CCI/UART/SPI）接收同一格式命令帧，汇入统一解析状态机。命令用 class / index / subcmd 三级字段定位，参数为定长 mode 字。构建配置决定启用哪些控制接口；多入口共享同一命令格式与解析状态机，避免每路各写一套协议——这是"一种协议、多物理口"的关键设计。

2路由与执行：单状态机 + 双消息层

多入口汇入同一个单命令状态机：仅空闲态接受新命令，处理中与收尾阶段新命令被拒绝。调用链为 命令解析路由 → 服务消息层 → 命令应用 → 应用消息层 → 业务应用。

  • 空闲态：接受新命令
  • 忙态：拒绝，返回错误
  • 收尾态：结果沿原入口返回，期间不接受新命令
注意：单状态机串行化多入口并发，从源头避免竞态；不能为每个控制入口各画一套可并行执行的命令状态机。

步骤 2 · 双消息层
调用链为 命令解析 → 服务消息层 → 命令应用 → 应用消息层 → 相机应用：路由层写服务信号，命令应用解析参数，业务应用订阅应用信号；中间层复制参数并投递信号，把协议解析与业务执行解耦。此段纯属固件消息链，无驱动与硬件参与。

3业务动作：切换预览与启动链路

命令的业务动作是切换预览：若当前流处于运行态，先同步停止旧预览，再启动新 mode。随后同步调用流配置服务，配置流管理器 / 节点 / 输出接口，经驱动与 HAL 启动像素处理链与输出接口。

  • 先停后启的同步序列，保证任一时刻只有一套配置生效
  • 停旧失败即返回，不是无缝双实例切换
  • 流管理器管状态机；节点管裁剪/缩放/叠加；输出接口管 USB / MIPI 绑定
关键：初始化预览成功不等于接收端已显示第一帧——链路就绪与帧显示是两个时刻。

4三条独立回传：结果 / 数据 / 事件

命令执行后有三条回传路径，逻辑与物理分离：命令结果沿原控制入口返回；视频数据由 DMA 与物理接口持续发送；硬件事件经 ISR / 回调上报。

通道方向载体特点
命令结果固件 → 控制主机CCI / UART / SPI少量控制字，原入口返回
视频数据硬件 → 接收端USB / MIPI持续大流量，不承载命令
硬件事件硬件 → 驱动 → 应用中断 / 回调状态标志，不承载整帧
三个观察点："命令成功""流运行""接收端看到完整帧"是三个独立观察点，不能混为一谈。

5时序与边界

结果语义与时序边界决定系统行为：

  • 只有启动成功才提交新 mode 并置激活标志
  • 失败不提交新 mode；旧预览已停也不自动恢复
  • 配置以同步调用串行完成，命令结果只在整条链路就绪后返回
验证闭环：验证一条命令时要分开确认命令结果、流状态与接收端帧，三者时间与含义各不相同。

一句话总结

命令协议用 class/index/subcmd 定位、单状态机串行路由、双消息层解耦执行，业务动作以先停后启切换预览；命令结果、视频数据、硬件事件三条回传独立分离，验证时须分开观察三个观察点。
