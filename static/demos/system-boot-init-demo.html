嵌入式系统启动链：从复位向量到第一帧

启动不是一跳进 main，而是分六步建立可运行系统：复位上下文 → 内存段复制与清零 → 硬件初始化 → 实时操作系统与调度 → 组件自动初始化 → 业务门控与预览投递。每一步都有明确的软件责任与硬件 / 内存结果。

  2. LMA / VMA 段复制与 BSS 清零
  3. 时钟、内存、中断的初始化顺序
  4. 调度器启动与 main 线程的关系
  5. 组件自动初始化的分级
  6. 业务门控与预览投递的异步边界

1复位上下文：向量、栈与 CSR

复位后寄存器不是 C 运行时状态。启动汇编先清通用寄存器，再建立 gp、异常向量、中断向量表与中断栈，之后才能安全执行段复制与 C 函数。

复位入口职责
  · 清通用寄存器 x1~x31
  · 设 gp（全局指针）、异常入口
  · 装载中断向量表与中断栈
  · CPU 进入机器模式
边界：此时外部内存尚未由本固件初始化，任何跳转与数据访问的目的地址必须是复位后可访问的片上资源。

2内存段复制与清零：LMA 与 VMA

链接脚本为每个段定义两个地址：LMA（镜像保存位置）与 VMA（运行访问位置）。有初值段（data 类）需要从 LMA 复制到 VMA；无初值段（bss 类）没有镜像初值，只需清零。

段处理
  · .data    LMA → VMA 复制（有镜像初值）
  · .bss     清零（无镜像初值）
  · 栈       由启动汇编装配
  · 片上段   先于外部内存段处理
关键区分：LMA 是镜像位置，VMA 是运行位置；无初值段只需 VMA 并清零。是否存在片上段分支取决于构建宏。

3硬件初始化：时钟、内存与中断

复位入口调 SystemInit 建立芯片基础设施：先配时钟与地址属性，再按构建变体初始化外部内存（DDR 或片内高速内存），最后使能中断控制器与 Cache。

外部内存就绪后，普通外存变体才会把外部内存段与各业务模块段从 LMA 复制 / 清零到位——顺序上必须先有内存，再写其 VMA。

坑："外部内存段在内存初始化前复制"是错误做法；"所有变体都执行同一组段复制"同样错误——DDR 与片内高速内存是构建变体，不应同时标为已执行。

4实时操作系统与调度

复位入口跳入 entry，进入实时操作系统主启动：先做板级初始化（UART、console、SysTick、heap），再创建 timer、scheduler、main 与 idle 等内核对象，最后启动调度器。

启动顺序
  entry → 内核启动 → 板级初始化
        → timer / scheduler / main / idle
        → 调度器开始调度
注意：main 线程在调度器启动前只是 ready，不会提前执行；组件初始化必须等到调度开始之后。

5组件自动初始化

调度器启动后，main 线程执行组件自动初始化：按优先级（板级、设备、组件、环境、应用）遍历自动注册表，板级组件在调度前的板级阶段已执行，等级 2~6 在 main 线程入口执行，最后才调用应用 main。

顺序：不能把所有自动注册都描述成在板级初始化中一次完成——设备 / 驱动注册完成后，组件才能安全使用对应硬件。

6业务门控与预览投递

main 是组件初始化后的业务入口，不是第一帧入口。自动预览启动先经过门控：检查升级 / 回滚状态、加载配置、读取参数；任一失败或未启用即结束。只有成功构造预览参数后，才经 RTE 信号把预览启动请求投递给后续业务上下文。

四个独立观察点："main 调用预览启动"、"预览请求已投递"、"视频链已启动"、"接收端看到第一帧"——它们依次发生，不能混为一谈。
