视频处理系统全景：从传感器到双输出的单条主链

一条从红外传感器出发的主链：像素经 IRSC 采集、ISP 校正、Video 处理与路由，最终分两路输出——一路走 USB 到 Windows，一路走 MIPI CSI-2 到外部接收端。控制、数据、事件三面共用同一套软硬件，但流向彼此独立。

  2. 传感器 → ISP → Video 的图像链路
  3. USB 与 MIPI 双输出的通道差异
  4. 控制面、数据面与事件面如何分离

1系统模块全景

整条主链可以按四层泳道组织：外部系统（Windows、CSI-2 接收端、控制主机）、固件软件（服务、stream、输出节点）、Driver/HAL（设备控制、ISR、DMA）、芯片硬件（IRSC、ISP、Video、USB、MIPI）。像素与命令都从这四层中穿过。

层主要模块职责
外部系统 / 业务Windows、CSI-2 接收端、控制主机消费帧、下发命令
固件软件服务、软件 stream、输出接口节点业务编排、缓冲所有权、接口绑定
Driver / HAL设备驱动、中断、DMA配寄存器、搬运数据、上送事件
芯片硬件IRSC、ISP、Video、USB、MIPI采集、校正、处理、路由、输出
主线：无论从哪一层看，像素都沿"传感器 → ISP → Video → USB/MIPI"单条主链前进；控制命令从主机进来，事件从硬件出去。

2图像链路：传感器 → ISP → Video

红外传感器输出 DN 像素流给 IRSC；IRSC 是红外 DN 输入口，ISP Pipeline 完成校正、降噪与测温；随后 Video 模块负责处理与路由——P/T/VS 流、SOUT 输出、MUX/SEL 选择。

缓冲所有权在软件侧：业务提供地址与尺寸，驱动写物理地址、长度与 stride 并维护 Cache，硬件 DMA 持续搬运帧。

注意：软件 stream 与硬件 stream 编号不是同一概念；用普通地址不自动等于 DMA 安全，仍需对齐、长度与一致性的显式维护。

3双输出：USB 与 MIPI

Video 的 SOUT 输出被两条通道消费，互不经过对方：

  • USB 通道：Video SOUT → USB 控制器 → UVC 封帧（Header / PTS / EOF）→ 端点 FIFO → USB PHY；以 endpoint 0x81 / 0x82 Bulk IN 标识，无虚拟通道 VC。
  • MIPI 通道：Video SOUT → Stream SEL → CSI TX（VC + DT + WC）→ D-PHY；以 VC 虚拟通道标识，data type 随输出格式变化。
维度USB 通道MIPI 通道
终点Windows usbvideo.sys外部主控 / FPGA / 桥片
通道标识endpoint 0x81 / 0x82（Bulk IN）VC 虚拟通道
组帧UVC Header / PTS / EOFCSI-2 VC + DT + WC
像素格式NV12 / YUY2 / Y16 / MJPEGYUV422 / RGB888-YUV444 / Y16 / Y14 / Y10 / Y8
物理输出USB PHYD-PHY（clock + data lane）
边界：USB 通道不经过 MIPI、MIPI 通道不经过 USB；VC 需按模式设置（如 NORMAL / SINGLE_VC_PIC / DUAL），endpoint 与 VC 是两类不同的通道标识。

4控制与数据分离

同一个系统里流动着三类信息：控制面（主机 → 服务 → 驱动 → 硬件）、数据面（IRSC / ISP / Video 的像素 → USB / MIPI 输出）、事件面（硬件中断 → 驱动 → 服务）。它们方向不同、语义不同，不能混为一谈。

  • 控制面承载命令请求与完成确认，不承载像素。
  • 数据面承载像素流，不经软件逐像素复制。
  • 事件面上送帧完成 / 溢出 / 错误，由明确等待或统计消费。
验证：命令成功、stream 状态与接收端拿到完整帧是三个独立观察点；端到端交付须分别覆盖配置、硬件状态与最终帧结果。

一句话总结

视频系统沿"传感器 → ISP → Video → USB / MIPI"单条主链工作，像素走硬件数据面、命令走控制面、状态走事件面——三面分离又闭环，构成一条确定、可验证的视频主链。
