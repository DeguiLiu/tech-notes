VC 与格式 为什么"设 VC"、格式哪里不同 —— 代码事实

VC 输出模式（相机头文件 / MIPI CSI TX 驱动）
NORMALVC=stream_idx 默认：VC 号与 stream 索引同号（virtualCh = stream_idx），一路流一个 VC
SINGLE_VC_PIC单 VC 单图 仅图像流占一个 VC；NV12 伪装 YUV422（data type 固定 YUV422_8bit）
SINGLE_VC_DUAL单 VC 双图 图像流 + 温度流上下拼接在同一 VC 输出；data type 同样固定 YUV422_8bit
MIPI data type 随 out_fmt 映射
格式 → CSI-2 data typeout_fmt YUV422 → YUV422_8bit ｜ RGB888 / YUV444 → RGB888_YUV444 ｜ Y16 → Y16 ｜ Y14 / Y10 / Y8 → 各自 ｜ SOUT420 使能时固定 Y16

配置事实 能力 / 编译输入 / 保存基线 —— 别混淆

MIPI 配置分三层：硬件上限 ≠ 本次编译 ≠ 另一保存基线
第一层 · 手册/硬件上限能力边界 最多 4 lane · 2.5 Gbps/lane · 硬件可描述 S0~S3。只表示能做什么，不等于本次启用
第二层 · 当前构建输入构建配置 现在：4 lane · 2 stream/控制器 · non-continuous clock · YUV422 8-bit。默认构建直接生效
第三层 · 另一保存基线保存基线 2 lane · 1 stream · non-continuous · RGB888/YUV444。与构建配置不同，仅可称保存基线
接收边界（务必理解）
MIPI 直接终点CSI-2 Receiver 是外部 CSI-2 接收端/桥片/主控/FPGA，不是 Windows；仅当桥片提供 USB/UVC 时 Windows 才在其后。仅凭配置无法证明板上固件与保存基线一致
